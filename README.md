# 山地地质灾害隐患巡查与治理工作台

面向隐患点建档、坡体形变与裂缝观测、雨量预警发布、避险搬迁与治理工程验收的山区地质灾害防治工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 本地开发一键复位

上一轮的工序编号、削坡方量、坡比要求、开挖高程都挂在浏览器 `localStorage` 里，
复现问题前不用再手动清存储，跑一条命令即可：

```bash
make reset          # 等价于 cd frontend && npm run dev:reset
```

命令会先做依赖体检（Node 版本、`node_modules`、vue/vite 等关键包，缺了会直接提示
先 `npm install`），通过后把播种版本号 +1。之后刷新浏览器：本地台账按最新示例数据
整体重新播种——削坡工序回到示例数据，治理工程等全部模块的清单条数一起回到初始。
只想体检、不改文件可以 `make check-deps`。脚本按自身位置定位仓库，克隆到任何目录
都能跑；浏览器端的重新播种逻辑见 `frontend/src/data/local-store.ts`（播种版本键
`geohazard-patrol:seed-version`）。

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：`make reset`（推荐），或清掉浏览器里 `geohazard-patrol:entries` 这一项、
  调用 `resetModule(模块)`。

## 削坡减载业务规则

规则集中在 `frontend/src/domain/`，台账页、统计卡、导入汇总共用同一套取数口径：

- **环节顺序流转**：待开工 → 施工中 → 待验收 → 已验收，只许逐环推进；回退与跳级
  （如待开工直接提交验收、已验收再开工）一律拦下，页面也只渲染当前环节允许的动作。
- **CSV 导入**：削坡页「导入削坡工序」，表头为 工序编号,所属工程,削坡方量,坡比要求,开挖高程；
  示例文件见 `frontend/samples/削坡工序导入示例.csv`。
- **重复导入按第一次已收处理**：工序编号已在台账里、或同批文件里重复出现的行整行跳过，
  不重复入库、不重复挂台账。
- **导入收尾驱动警示标识台账**：每批有新收工序时，`signboard` 自动新增一条「待核对工序」
  （状态待设置，引用本批工序编号）；整批都是重复时不新增。
- **削坡方量统一取数**：列表统计卡、页脚累计、导入汇总都走 `domain/cutting.ts` 的
  `parseVolume` / `sumCuttingVolume`（支持 `1200`、`"1,200方"`、`"1500 m³"`，无法识别即拒收/不计入）。
- **坡比与高程的优先级**：坡比要求有效时以坡比为准；坡比无效或缺失、开挖高程有效时
  按高程控制（结果写入「设计依据」列，坡比无效的工序挂「待核对」异常）；两者都不可用整行拒收。
- **坡比超范围按无效处理**：坡比系数（`1:n` 的 n）业务范围 0.5～2，陡于 1:0.5 或缓于 1:2
  （含写反成 `1:6`、`7.5` 这类值）一律按无效，不参与坡比判定。
